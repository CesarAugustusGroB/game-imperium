El trato en una línea

El 1.er asiento ocupado fija la misión (Fase 1). Cada asiento siguiente ocupado, además de su modificador de stats, siembra una mini-quest: una carta-quest dedicada que aparece al llegar a su ubicación y debe jugarse antes de que expire su ventana de turnos.

OrigenAsientos no-misión ocupados (2.º, 3.º…)
ColorTema + recompensa (fija)
PassiveModula la ventana (tier → margen)
UbicaciónAleatoria entre las 3 del medio, sin repetir
Al fallarPenalti temático por color

Ciclo de vida de una quest

Embark: asigna color · ubicación · ventana → pending → llegas a la ubicación → inyecta carta → active (timer = ventana) → jugar = completed / expira = failed + penalti

La recompensa son los effects de la carta y el costo su cost → reusa el flujo playCard/applyEffects tal cual. La ventana es el expiry y el penalti reusa el path de penalty() de los compromisos, desviado a tracking de quest (no infla brokenCommitments).

Arquitectura (respeta el desacople de Fase 1)

data iter-belli-quests.ts Nuevo

Data pura — no importa advisor/run.

  • SECONDARY_QUESTS: Record<QuestColor, SecondaryQuestDef> — por color: título, desc, cost, effects (recompensa) y penalty (fallo).
  • makeQuestCard(quest): OperationCard — fábrica que construye la carta desde la asignación. La importa el módulo de estado.

data iter-belli-consilium.ts Extender

Ya es el bridge advisor-aware (vive aquí computeConsiliumSetup de Fase 1).

  • computeSecondaryQuests(slots): SecondaryQuest[] — salta el 1.er asiento ocupado (misión); por cada asiento siguiente ocupado: color→quest, currentTier→ventana, asigna ubicación media aleatoria sin repetir.

game iter-belli-types.ts Extender

  • SecondaryQuest { id, color, title, locationId, window, status } + QuestStatus = 'pending'|'active'|'completed'|'failed'.
  • Añadir quests: SecondaryQuest[] a IterBelliState y quests? a CampaignSeed.
  • Añadir questId?: string a OperationCard.

game iter-belli-state.ts Extender

  • startIterBelliCampaign guarda seed.quests en S.quests (status 'pending').
  • injectLocationQuests() — estilo injectCrises, llamada en endTurn y al startear: por cada quest pending cuya locationId === currentLocation().id, hace unshift de la carta (timer = window) y la marca 'active'.
  • playCard — si la carta tiene questId, marca esa quest 'completed' (la recompensa ya la aplicó el flujo normal).
  • endTurn (loop de expiración) — si expira una carta con questId, marca 'failed' y aplica penalty() temático, sin contarla como brokenCommitment.

data iter-belli-balance.ts Extender

QUEST_WINDOW_BASE = 3 (ventana = base + tier−1 → 3/4/5).

ui Puentes & presentación Extender

  • EmbarkCard.tsx — computa computeSecondaryQuests(councilSlots) y lo pasa por el seed (junto al mission/modifiers de Fase 1).
  • IterBelliScreen.tsx — bajo la línea de misión, lista las quests active (título + turnos restantes).
  • EndgameCard.tsx — lista cada quest con su estado (cumplida / fallida / no activada).

Por qué encaja

  • La recompensa son los effects de la carta y el costo su cost → cero sistema de recompensa nuevo.
  • La ventana es el expiry y el penalti reusa el path de penalty() ya existente.
  • Lo único nuevo: bridge de asignación + quests[] en estado + inyección por ubicación + marcado de status. Mínimo y aislado, como Fase 1.
